# マイク・スマートフォンで実際のスピーカー音を記録する

v0.5.0では、デジタルのループバック録音に加え、PCのマイク入力と、スマートフォンの音声・動画の取り込みを利用できます。特定のPCやスマートフォンのメーカーには限定していません。録音はユーザーの操作で開始し、クラウドへ自動送信しません。

## PCにマイクを挿す場合

1. `start.cmd`を開き、PC情報を収集するか既存の記録を再開します。
2. 「テスト音声・録音・聞き直し」タブで「出力一覧を取得」を押します。
3. 「録音元・マイク」を「接続したマイク入力」にし、使用するマイクを選びます。基準音を流す／聞き直す出力も選択します。
4. マイクをスピーカー近くに置き、小音量から始めます。「共通テスト音声を再生して録音」または「他アプリの音を録音」を選び、内容確認のチェックを入れて開始します。
5. 停止後、通常の比較テスト中ならそちらも終了し、保存WAVを再生して照合結果を保存します。

マイクには部屋の音、距離、向き、入力レベル、ノイズ抑制などの処理も影響します。ノイズが録れなかったことだけでPCが正常とは判断しません。Windowsのマイク許可でデスクトップアプリからの入力が禁止されている場合は、設定を確認するかスマートフォンを利用してください。ツールはマイク許可や音声設定を変更しません。

## スマートフォンをQRで接続する場合

### PC側

1. PCとスマートフォンを同じWi-Fi・ルーターへ接続します。信頼できる自宅などのネットワークで使ってください。
2. PC情報を収集し、「スマホ・実音取り込み」タブを開きます。
3. 「LANアドレスを取得」でスマートフォンと同じLANのアドレスを選び、「受付を開始」→「QRコードを表示」を押します。
4. 開いたページのQRをスマートフォンで読み取ります。受付は15分で終了し、再開すると新しいQRになります。Windowsがネットワーク通信の許可を求めた場合は、使用するプライベートネットワークだけを許可してください。ファイアウォールの設定をツールが自動で変更することはありません。

### スマートフォン側

1. QRのページを開き、「音声を録音・選択」または「カメラで動画を撮影」を選びます。短い10〜30秒程度の記録から始め、スピーカー近くで音を拾います。
2. 端末の録音アプリが選択肢に出ない場合は、動画撮影か、ボイスメモ等で保存した記録を「保存済みの音声・動画を選択」から選びます。
3. ページに戻って記録を聞き直し、ノイズの有無や備考を入力します。
4. 「この記録をPCへ送信」を押します。送信ボタンを押すまではPCへアップロードしません。PCの一覧に受信結果が追加されます。

### PCで聞き直す

受信一覧から「ブラウザーで再生」を押します。再生後、「元の記録を再生確認した」にチェックを入れ、聞こえ方と再生経路を記録して保存します。この確認は人の手動申告として保存し、ブラウザーで最後まで自動確認したという意味にはしません。再生できない形式は元ファイルを対応するプレーヤーで開くか、スマートフォン側で別の形式として保存してください。

PCのループバック録音と組み合わせる場合は、先にPCで共通音声・録音を開始してからスマートフォンで記録します。受信時に選択されているPC録音／実行中のテストとの関連を保存します。比較条件を変えないため、撮影位置・音量・素材を維持し、ファイル送信は音声の再生・録音を終えてから行うのがおすすめです。端末とPCの時計は自動同期していないため、受信時刻を録音開始時刻として扱わず、自動の波形一致や遅延測定は行いません。

## クラウドなしで実現する方法とブラウザーの制限

PCが選択したプライベートIPv4アドレスと一時ポートで小さなHTTPサーバーを開き、同じLANから記録を受け取ります。Cloudflare、公開トンネル、STUN/TURN、外部QR生成API、CDNは使いません。QR生成コードはMITライセンスの[qrcodejs](../web/vendor/qrcodejs/SOURCE.txt)を固定コミットで同梱し、PC内で動かします。

`getUserMedia()`によるページ内マイク録音は、HTTPSやlocalhost等の安全なコンテキストを必要とします。スマートフォンからPCの `http://192.168...` を開いても、スマートフォンにとってlocalhostではありません。証明書を信頼させたりブラウザーのセキュリティを無効化したりせず使うため、通常のLAN接続では**端末の録音・カメラへの引き渡し／保存済みファイル選択**を用意しています。`capture`属性は端末へのヒントなので、表示される録音・カメラの選択肢は端末・ブラウザーによって異なります。

安全なコンテキストでMediaRecorderが利用可能な場合だけ、ページ内録音のボタンも表示します。これも自動ではマイクを使わず、押したときに許可を求めます。通常のスマートフォンLAN接続で必ず直接録音できる、と表示することはありません。

LAN内HTTP通信は暗号化されません。公開・共有Wi-Fiではなく信頼できるネットワークを使用し、終わったら「受付停止」を押してください。接続URLのランダムなトークン、HostとOriginの確認、15分の期限、1ファイル128MB・1受付12件／合計512MBの上限を設けています。受信サービスから任意のセッションファイルをダウンロードすることはできません。設定の自動変更や公開ネットワークへの待ち受けは行いません。

## LANからつながらない場合

- 選択したLANアドレスと、スマートフォンのWi-Fi接続先を確認します。モバイル通信、VPN、ゲストWi-Fiの端末間通信禁止、ルーターのクライアント分離が影響する場合があります。
- Windowsのファイアウォールを全面無効化せず、必要なプライベートネットワークのアプリ通信だけを確認します。QRの期限が過ぎたら再開して読み取り直します。
- 接続が難しければ、スマートフォンの録音・動画をUSBケーブル等でPCへコピーし、同じタブの「ファイルを取り込む」を使えます。クラウドは不要です。

## 保存と持ち帰り

v0.6以降は、録音と受付を終了して**データを書き出す**を押すと、元の音声・動画も含むZIPを作れます。[書き出しと解析の手順](data-workflow.md)を参照してください。

音声・動画は変換せず元の形式とSHA-256を保存します。対応するコンテナーはWAV、M4A／MP4、MOV、WebM、Ogg、MP3、AACです。受信時の形式確認はコンテナー署名の確認であり、全コーデックの再生や録音内容の正常性を保証するものではありません。

```text
data/sessions/<実行ID>/
  session.json
  report.html
  audio/<PC録音ID>/microphone.wav   # PCマイク録音の場合
  physical/<取り込みID>/source.*   # スマートフォン等の元ファイル
```

`audio`・`physical`を含む**セッションフォルダー一式**を持ち帰ってください。「記録を再開」で別の場所から読む際にも、対応する元ファイルをハッシュ確認してコピーします。スマートフォン側の元ファイルは削除しません。QRのURLやトークン、送信元IP、元ファイル名は調査ログへ保存しません。入力した備考と、録音が拾った会話・周囲の映像には個人情報が含まれ得るため、共有前に確認し、公開リポジトリへ追加しないでください。

## 根拠と検証範囲

- [MDN: getUserMediaと安全なコンテキスト](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)
- [web.dev: ファイル入力・capture属性を使う録音](https://web.dev/articles/media-recording-audio)
- [qrcodejs原本・MITライセンス](https://github.com/davidshimjs/qrcodejs)

ローカル受信API、元ファイル保持、受付停止・期限、実ブラウザーでの偽マイク録音と送信、非安全コンテキスト時のフォールバック、QR生成を自動検証します。スマートフォンの実機カメラ・録音アプリの選択画面は端末依存です。診断対象のスピーカー音やマイク感度の確認は実機で行ってください。

開発用のブラウザーテストはNode.js 22以降とChromeがある環境で `node .\tests\test-phone-browser.mjs` を実行します。これは開発・検証用であり、配布アプリの利用にNode.jsやChromeの追加インストールは不要です。テストは隔離プロファイルと偽マイクだけを使い、普段のブラウザーや実マイクには触れません。QR生成に同梱する第三者コードのライセンスは[MIT原文](../web/vendor/qrcodejs/LICENSE)を参照してください。
