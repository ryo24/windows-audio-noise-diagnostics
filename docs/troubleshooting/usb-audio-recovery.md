# USB音声の周期ノイズを復旧する

内蔵3.5 mm端子やUSB音声機器で周期的なノイズが出る場合の手順です。まず音を使える状態に戻す方法を選び、内蔵端子を使い続ける場合は復旧操作と再発の有無を確認します。

## 別の出力で音を確保する

1. ノイズが出ないことを確認したHDMIや別の音声出力を、Windowsの **設定 → システム → サウンド → 出力** で選びます。テレビにイヤホン端子があれば、同じスピーカーをそこにつなげます。手元に別のUSBオーディオアダプターがあれば、そのアダプターを出力先にして同じスピーカーをつなぐ方法もあります。
2. 普段と同じ用途で使い、スリープ復帰後や従来症状が出ていた使い方でも再発しないか確認します。安定すれば、その経路を普段の出力として使えます。内蔵端子へ戻すときは、出力先と接続を元に戻します。

## 内蔵端子をPC再起動なしで復旧できるか試す

この操作は、対象出力の背後にある **USB複合デバイス** を一度だけ再起動します。その機器の音声・マイク・ボタンなどが一時的に切れます。同じ出力を使う再生・通話・録音を止めてから実行してください。別の出力で音を確保済みであれば、症状が出ているときに内蔵端子を試せます。

1. 対象PCでアプリを閉じ、利用版のフォルダーで `update-develop.cmd` を実行します。利用版から取得した場合、開発版フォルダーは `data/develop-tool/` です。すでに `develop` のフォルダーで更新した場合は、そのフォルダーを使います。
2. デバイス マネージャーの **オーディオの入力および出力** で対象の再生出力の名前を確認します。以下は `Speakers (USB Audio and HID)` の例です。実際の名前に置き換え、開発版フォルダーで対象を確認します。この段階では機器の状態は変わりません。

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Restart-UsbAudioDevice.ps1 -EndpointName 'Speakers (USB Audio and HID)'
   ```

3. 表示された出力とUSB複合デバイスが合っていれば、**管理者として開いたPowerShell**で開発版フォルダーに移動し、同じコマンドに `-Apply` を付けて実行します。PC全体の再起動を要求するオプションは指定していません。対象が一意に特定できない、USB音声機能から親機器につながらない、またはPnPUtilがエラーを返す場合はそこで止めて、表示を控えてください。 [MicrosoftのPnPUtil構文](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax#restart-device)

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Restart-UsbAudioDevice.ps1 -EndpointName 'Speakers (USB Audio and HID)' -Apply
   ```

4. Windowsで同じ出力を選び直し、`mmsys.cpl` の再生デバイスのプロパティから、直前と同じ既定形式でテスト音を聴きます。例えば発生時に48 kHzだった場合は48 kHzを維持します。直後の結果、後で再発したか、再発までの使い方を記録します。取得済みの正常音は聞き比べの対照に使えます。

## 結果から次の対応を選ぶ

| 結果 | 次の対応 |
| --- | --- |
| 再初期化後も普段の使い方で再発しない | そのまま使い、スリープ復帰など従来の発生条件でも確認する。 |
| 一度消えるが再発する | 一時復旧として扱う。長く使える出力を確保し、内蔵端子が必要なら、再発条件と下記の機器情報を添えてメーカーの対応を確認する。 |
| 同じ3.5 mm出力で直後も続く | 再初期化の繰り返しを省き、安定している別経路を使う。内蔵端子の復旧は、適合するメーカー修正の確認か、端子・内蔵音声機器の点検に進む。 |

メーカーのドライバーやファームウェアは、PCの正確な型番・Windows版と、コマンドが表示したUSB音声機能のハードウェアIDを伝えて、対象機器への適用と症状への対応を確認します。音声機能に対応すると確認できた署名付きパッケージだけをメーカー手順で試し、元の版と戻し方を控えます。正常時と発生時で現在のドライバー版が同じ場合、その比較だけでは入れ替える版を選べません。更新直後から発生し、直前の版では安定していた証拠がある場合は、デバイス マネージャーの **ドライバーを元に戻す** が候補です。[Microsoftの音声ドライバー手順](https://support.microsoft.com/en-us/windows/hardware/audio/fix-sound-or-audio-problems-in-windows)

USBトレースを根拠にメーカーへ相談する場合は、発生時のノイズの間隔、実音での音程変化、再初期化の結果を添えます。USB転送のリクエスト完了が規則的でも、パケットごとの実データ量や同期情報が取れていなければ、どの段階の異常かは特定できません。追加計測は、メーカーが必要とする情報や、症状時と正常時で比較できる情報が明確になった段階で行います。
